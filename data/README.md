# データセット（20クラス → 100クラス）

## 最初の撮影
緑20枚を **D01～D20の順番** に真上から同じ高さで1枚ずつ撮影し、`data/raw/green20/top/h01/` に保存してください。札全体・四隅・黒背景の余白を写し、照明とカメラを固定します。

写真は一旦カメラ標準の名前のままで構いません。**ファイル名の昇順と撮影順が一致することが必須**です。撮り直しや削除があれば撮影順を再確認してください。

`data/metadata/green20_cards.csv` がD01～D20と百人一首の札番号の正しい対応表です。20クラスのYOLO内部IDはこのCSVの行順に0～19、表示名は札番号（例: 008）とします。100クラスでは札番号001～100を内部ID0～99へ対応させます。

## 一括リネーム

PowerShellでプロジェクト直下から実行します。

```powershell
uv run python scripts/rename_green20.py
```

20個の変更予定が表示されます。**札番号とファイル名の対応がすべて正しいことを確認**した場合だけ実行します。

```powershell
uv run python scripts/rename_green20.py --apply
```

出力例: `card_008_top_h01_s01.jpg` （札番号008／真上／高さ1／撮影セッション1）。

将来の撮影では、高さが違う写真を別フォルダに保存して `--folder data/raw/green20/top/h02 --height h02` のように指定できます。毎回20枚・D01～D20の順番が前提です。元画像は必ずバックアップしてください。

## 今後のデータ設計

- `raw/`: 実写画像のみ。元画像は編集・上書きしない
- 回転拡張: 学習用の元画像を0～355°（5°刻み）で生成。**分割前に拡張しない**
- アノテーション: 札の四隅を取得して保存し、通常のYOLO Detect用の `class_id x_center y_center width height` を自動生成（値は0～1）
- 単札の独立した検証・テスト画像は別撮影で確保する
- 推論評価では、複数札画像にも正解ラベルを付けて、誤識別・未検出・推論時間を測定する
- 照明条件は今後追加する

`raw/` の画像、生成データセット、重みファイルはGitHubで管理しません。コード・メタデータ・設定ファイルだけをGitHubで管理します。
