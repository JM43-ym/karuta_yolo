# 2026-11-26 ゼミ後のYOLOデータ見直し計画

作業開始：2026-11-26 17:00（本人申告）。以下は**提案・計画**であり、撮影・再抽出・再学習・新規データ生成はまだ実施していない。

## 背景

ゼミ発表で「30°・45°の固定角度画像は、想定する撮影条件から考えると不要ではないか」との指摘があった。実際の推論対象は、競技配置の緑20札をほぼ真上から撮影した画像（例：`competition_003.png`）。これに合わせて、動画のLR/FBフレームから正面に近い視点を優先して選ぶ方針を検討する。**固定角度画像の削除や従来モデルの上書きは行わない**。

## 1. 正面に近いフレームの抽出

現行の `scripts/capture/extract_karuta_frames.py` は、動画の画像変化量の累積を用いて、全区間から既定5フレームを選ぶ。これをそのまま実行しても**正面に近い5フレームにはならない**。取得元動画に物理角度の情報はないため、進行度の中央 = 必ず正面、とは限らない。

提案：
1. LR / FB 動画ごとに正面にもっとも近いフレームを目視で特定する。
2. その前後から傾きが浅く、ブレ・反射の少ないフレームを選び、原則5フレームにする。物理角度が確認できれば0°付近と±数度～15°程度を検討するが、未校正の動画には実角度ラベルを付けない。
3. 画像の元サイズを維持し、各抽出画像の元動画名・フレーム番号・選択理由をCSVで保存する。
4. 古い抽出PNG／アノテーションは保持し、別バージョンで保存する。新しい抽出画像は**再アノテーション**してから学習に使用する。
5. 従来の固定角度データを保持した比較モデルと、正面近傍に絞った新モデルを**同じ独立評価条件**で比較する。固定角度画像の「不要」という結論は比較後に判断する。

**注意**：この提案の抽出位置を自動選択する機能は現行スクリプトにまだ追加していない。既存の抽出スクリプトを無条件に再実行・`--replace`しないこと。

## 2. 緑20枚の競技配置テストのフォルダ

学習データと明確に分け、密着配置と間隔あり配置を同じレベルで管理する。両者は可能なら札の並び順・カメラ高さ・照明・画像サイズを同じにし、札の間隔のみを変える。

```text

├── competition/
│   ├── touching/            # 札を詰めた従来配置
│   │   ├── competition_001.png
│   │   ├── competition_002.png

│   └── spaced/              # 同じ並びで札間を空けた新規撮影
│       ├── competition_spaced_001.png
│       ├── competition_spaced_002.png
│       └── ...
└── scattered/               # 既存の散らし配置用（変更しない）
```

- このフォルダ構成は**提案**。Gitの`.gitignore`により実画像は通常GitHubには含まれず、研究室PCでフォルダ作成・整理する。
- 既存の `competition_001.png` などの実保存場所を確認し、元データのバックアップ後に整理する。既存の推論コード・記録GUIが参照しているパスも必要に応じて更新する。
- 正解札・検出枠のアノテーション、手動集計の `review.json`、推論したモデルや`imgsz`/`conf`値を保存して比較できるようにする。
- 既にモデル選択・閾値調整に使った画像は、厳密には独立した最終Testではなく開発評価用。最終性能の測定には未使用画像を分けておく。

## 3. h01再撮影と3倍率の再計算

現在の `scripts/dataset/build_green20_video_augmented.py` では、h01/h02/h03の**札面積 / 画像面積の平方根**の中央値で札の見かけの大きさを測り、h01=1を基準にh02/h01・h03/h01の倍率を求める。過去の日誌では2026-11-20時点の旧値が `h01=1.00000, h02=0.56481, h03=0.37612` だったが、再撮影後は再計算が必要。

- 旧撮影画像は `data/raw/green20/train/single/top/h01_s03/` で保存し、旧アノテーションも新s01のものと区別して保管する。旧ファイル名の `s01` 表記は中身と一致するよう整理する。
- **新しいh01は `data/raw/green20/train/single/top/h01_s01/`** に撮影し直す。旧h01は `h01_s03/` に保存し、新s01の画像やアノテーションとは混ぜない。
- 新しいh01の全20枚について、札番号と四隅アノテーションを再取得・目視確認する。
- h02/h03は従来の撮影を使う場合、両者の撮影条件の違い・画角・解像度・光量に注意する。
- 現行データセット生成スクリプトはh01の`s01`を固定参照している。**新しい`s01`を撮影・アノテーションした後で再計算する。** 旧s03は比較・保管用とし、新規学習用の読み込み先には使わない。
- 新データセットは旧 `data/datasets/green20_video_augmented/` に上書きせず、別名で作成する。新しいアノテーションと動画抽出の変更分を含めてから生成する。

## 4. 比較のポイント

- 札の密着と間隔ありそれぞれで、未検出位置・未検出札・誤分類を10画像単位で集計する。
- 同じモデル・同じ`imgsz`・同じ`conf`で配置条件だけを比較する。
- 従来モデルと正面近傍モデルの比較では、学習画像枚数や検証条件の差を記録し、どの変更が効いたか解釈できるようにする。
